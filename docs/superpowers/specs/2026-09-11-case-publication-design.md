# 发布唯一的生产线平衡改善案例

## 目标

让已授权的企划人员发布一条立即可供内部员工查阅的生产线平衡改善案例。案例必须具有唯一的案例名称、可选案例说明，以及一个不超过 200 MB 的 PowerPoint 文件。

## 接口与流程

`POST /api/ppts` 继续作为发布案例的公开 HTTP 接缝。只有通过现有企划鉴权的请求可以创建案例。

服务端在处理上传时验证：

- 案例名称在去除首尾空白后不能为空。
- 文件扩展名必须是 `.pptx` 或 `.ppt`，且大小不超过 200 MB。
- 案例名称必须与现有案例的名称完全不同。

若发现同名案例，服务端删除本次已落盘的临时文件，返回 `409 Conflict`，并携带稳定案例 `id` 和名称。不会创建记录、解析预览或静默覆盖任何现有文件。

上传界面先在浏览器中提示空名称、不支持格式和超限文件；服务端仍执行相同验证。收到 `409` 后，界面显示冲突案例名称，提供“替换现有案例”和“返回修改名称”。前者以该案例的 `replaceCaseId` 明确重新提交；后者保留已选文件和填写内容，供企划人员修改名称。

本 issue 中的显式替换复用现有案例记录，使其在成功提交时仍能被内部员工通过同一稳定链接读取。完整的文件替换原子性、旧预览清理与失败回滚属于后续“替换案例文件”工作，不在本 issue 扩展。

## 数据与可见性

成功的新案例沿用当前存储格式写入 `ppts.json`，并产生其下载 URL。写入成功响应后，免登录的 `GET /api/ppts` 将立即包含该案例，满足内部员工即时查阅。

## 错误处理

无效文件、超限文件和空名称返回可读的 `400` 错误。非企划请求继续返回现有鉴权错误。未知的 `replaceCaseId` 或不匹配的名称不可用于替换，并返回冲突/验证错误。失败路径须清理本次新建的临时文件和预览目录，不影响既有案例。

## 验证

以 HTTP 上传接口为测试接缝，验证：

1. 非企划人员不能创建案例。
2. 上传只接受 `.pptx`/`.ppt`，并拒绝超过 200 MB 的文件。
3. 空案例名称被拒绝。
4. 同名上传返回 `409`，不会静默覆盖既有案例；显式替换才允许继续。
5. 成功创建的案例可立即从免登录案例列表读取。

测试不读取路由私有状态；以隔离目录保存测试数据与上传文件。

## 范围边界

不改变企业网络边界、SSO/企划权限的既有实现、案例阅读免登录行为或下载计数。不会引入分类必填、标签必填、版本历史或自动线平衡功能。
