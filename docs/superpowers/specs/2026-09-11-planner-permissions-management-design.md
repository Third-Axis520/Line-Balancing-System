# 企划权限管理设计

## 目标

完成 GitHub Issue #5：管理员可为单个 Microsoft Entra 身份授予、查看和撤销企划人员权限。企划人员可继续维护所有生产线平衡改善案例；内部员工在企业网络边界内仍无需应用登录即可浏览、预览与下载案例。

## 边界

授权记录以 Entra Object ID（OID）为唯一键保存。系统不根据部门、姓名、邮箱或其他目录资料自动授予企划权限；这些字段只用于管理员查找和辨识身份。

管理员角色仍由现有本地 `auth.json` 的 `admins` 记录及受控 bootstrap 配置决定。本次只管理 `planners`，不增加管理员角色的授予或撤销功能。

## 管理体验

已登录且目录资格合格的管理员可从个人菜单打开“企划权限管理”。企划人员和访客不显示该入口。

管理页面包含：

- 当前企划人员清单：显示姓名、邮箱与 OID，并可逐一撤销权限；
- 添加区域：管理员可输入姓名或邮箱搜索目录并选中员工，也可直接粘贴 OID；
- 明确的加载、空状态、成功与失败反馈。

直接 OID 与目录搜索都会调用相同的角色变更 API，最终只提交 OID。重复授予应保持幂等并显示为已拥有权限；撤销不存在的记录同样保持幂等。

## API 与数据流

保留并使用现有管理员专用接口：

- `GET /api/admin/planners` 返回已获授权的 OID 列表；
- `PUT /api/admin/planners` 接受 `{ oid }` 并授予企划权限；
- `DELETE /api/admin/planners/:oid` 撤销企划权限。

新增 `GET /api/admin/directory-search?q=...`。该路由必须要求合格管理员身份，接受去除首尾空格后的查询；只有长度至少为 2 的姓名或邮箱关键字才会触发上游目录查询。响应最多返回有限数量的 `{ oid, name, email }` 身份候选项；不得向浏览器暴露上游目录地址、部门、状态或目录全量资料。

目录搜索失败时使用现有安全错误结构，目录不可用返回 `503 DIRECTORY_UNAVAILABLE`。前端通过既有 `callApi` 附带 Entra access token。所有角色写入仍由后端执行 OID 格式校验、锁定与原子持久化，因此变更即时生效。

为显示既有授权人员的名称与邮箱，清单接口扩展为在不泄露不相关目录资料的前提下提供可用的身份摘要；若目录查询暂时不可用，仍返回已授权的 OID 并让前端继续允许撤销。

## 验证

HTTP 集成测试覆盖：非管理员无法搜索、读取或修改；管理员可按搜索结果对应的 OID 授权并立即使该身份获得案例维护权限；撤销后立即失去维护权限；搜索参数校验与目录故障的安全失败；读者 API 仍免登录。

前端类型检查覆盖组件与 API 类型；完整验证运行 `npm run lint`、`npm test` 与 `npm run build`。
